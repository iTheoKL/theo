Project Archiviette — A Student Tracker Project
Three Apprentices Who Know Nothing Attempt to Build Something

We decided to build Archiviette, a student attendance and marks tracking system for our class. Why? Because spreadsheets are dull, nobody maintains them properly, and besides, our collective résumé currently peaks at "can print Hello World" before falling promptly off a cliff.

The team is me, Pacman, and Dino. Three people whose entire programming experience amounts to printing "Hello, world!" in Python and feeling far too pleased with ourselves afterward. We don't know Flask. We don't know React. We don't know SQLite. We barely know what JSON actually is, beyond that it's pronounced the same as Jason. And somehow, this felt like precisely the right moment to start a real project.

The Current State — Empty Folders and Delusion

Right now, Archiviette exists as a GitHub repository with four empty folders (frontend/, backend/, database/, docs/), a default README, and an MIT license we added because every serious-looking repo has one and we didn't want to look unserious.

No code. No logic. No features. Just empty directories, misplaced confidence, and the belief that this will eventually become something worth using.

Division of Labor (Mostly Guesswork)

We split things up in the most sensible way we could think of, which is impressive considering how little of this we actually understand.

Pacman is handling the database, which means learning SQL, designing tables, and understanding why foreign keys exist instead of simply winging it. Dino is on frontend duty with React, which means wrestling with JSX, components, state, and why one missing bracket can bring the whole app down. I'm doing the backend with Flask, which mostly involves learning routing, APIs, and why nothing works the first time you run it.

None of us are specialists. We're learning just enough to move forward, breaking things constantly, searching the internet like our lives depend on it, and slowly piecing together how all these parts are meant to talk to one another without collapsing.

The Tech Stack

We're using React, Flask, and SQLite, largely because every beginner tutorial on the internet insisted they were "simple" and "beginner-friendly." At this stage, beginner-friendly mostly means "there are enough forum threads out there that someone else has already suffered through this exact problem."

The goal is to keep it aggressively simple. No fancy dashboards. No overengineered analytics. Just login, attendance tracking, and exam marks. If those three things work reliably without taking the database down with them, we're calling it a success.

The Learning Strategy

We're using AI tools like ChatGPT, Copilot, and Claude as explanations and guardrails, not as "do everything for me" buttons. The idea is to actually understand what's happening, write most of the code ourselves, and sit with the discomfort of fixing our own mistakes.

Is this the fastest way to learn? Probably not. Is it honest? Yes. We're not trying to speedrun competence — we're just trying not to quit halfway through.

Git & GitHub

We know the basics: clone, add, commit, push. Everything beyond that currently feels like uncharted territory. Merge conflicts sound dreadful. Branching seems unnecessary right up until the exact moment it becomes mandatory. Commit messages are mostly vibes.

We are fully expecting to get this wrong at least once. Possibly in a very public, very educational way.

The Timeline (Very Optimistic)

Week 1: Get Flask running, render literally anything in React, and create a SQLite table without breaking it.

Week 2: Make everything talk to each other. Frontend to backend. Backend to database. Minimal panic.

Week 3+: Start building actual features — login, records, attendance, marks.

We have absolutely no idea whether this timeline is realistic. Reality will let us know soon enough.

Why This Matters

Archiviette isn't going to change the world. It probably won't even look impressive for a while. But it's ours. It's the leap from "I followed tutorials" to "I built something people can actually use."

We're okay with being bad at this for a while. That's how learning actually works, even when it's uncomfortable.

What Happens Next

We'll keep updating this as we go. When things work, we'll write about it. When things break — and they certainly will — we'll write about that too.

And we'll include the repo link once there's something worth showing. For now, it's just an empty private repo.
