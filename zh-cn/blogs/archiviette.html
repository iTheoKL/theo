Archiviette

Archiviette 项目 - 由三个一无所知的学徒搭建的学生记录系统,以及“依然选择动手开始”所意味着的一切。

我们决定为班级搭建 Archiviette,一套学生出勤与成绩记录 系统。表格软件也能存住同样的信息,但表格从不向使用它 的人提出任何要求,也从来没有谁真正负责维护它。我想要 一样真正对自身结构负责的东西,也想成为那个理解"为什么" 的人。

团队成员是我、Pacman 和 Dino。我们三人加起来的编程经验, 大概就是用 Python 打印过一句"Hello, world!",并为此 相当满意。我们不懂 Flask,不懂 React,不懂 SQLite,对 JSON 的理解基本停留在它怎么读。不知为何,那感觉恰恰就 是开始一件真正的事情的最佳时机。

现状:空文件夹与一份意图

目前,Archiviette 只是一个 GitHub 仓库:四个空文件夹 (frontend/、backend/、database/、docs/)、一份默认的 README,以及一份 MIT 许可证 - 之所以加上后者,是因为 一套认真的结构,从一开始就该显得认真。

没有代码,没有逻辑,暂时也没有功能。只有它将来会成为 什么样子的轮廓,以及一份我们打算认真遵守的计划。

分工

我们按照当时觉得最合理的方式分了工 - 尽管我们对自己 正在划分的这片"地形"几乎一无所知。

Pacman 负责数据库:学习 SQL、设计表结构、理解外键存在 的意义,而不是把每张表都当成一座孤岛。Dino 负责 React 前端,这意味着要学习 JSX、组件、状态管理,以及少了一 个括号是怎样能拖垮整个界面的。我负责用 Flask 搭后端, 主要就是学习路由、API,以及为什么没有一次是第一次尝 试就能正常跑起来的。

我们没有一个人是自己所承担部分的专家。我们只是学到刚 好够继续前进的程度,时不时把东西弄坏,然后慢慢摸索这 些各自独立的部分该如何彼此"对话",而不至于让整个结构 垮掉。

所用之器

我们选择用 React、Flask 和 SQLite 来搭建,很大程度上 是因为我们找到的所有入门资料都说它们"容易上手"。在这 个阶段,"容易上手"多半意味着:我们即将遇到的那个问题, 已经有别人写好文档了。

我们的意图是刻意让系统保持简单。没有花哨的仪表盘,没 有超出必要范围的数据分析。登录、出勤、考试成绩 - 就 这三样。只要这三样能稳定运作,而不把数据库一起拖垮, 那就够了。

我们如何学习

我们把 ChatGPT、Copilot 和 Claude 这类工具当作解释与 护栏来使用,而不是把工作整个交给它们。目的是真正理解 我们写下的代码底层发生了什么,并愿意坐下来忍受修正自 己错误的那种不适,而不是找别的东西替我们修。

这不是通往能力最快的路径。但我认为,是最诚实的一条。 我们要的不是快点抵达,而是不要停下来。

Git and GitHub

我们掌握了基础操作:clone、add、commit、push。再往后 的东西大多还没探索过。分支(branching)在真正变得不可 或缺之前,似乎都显得没什么必要。至于提交信息,目前基 本全靠直觉。

我们预期至少会在这上面栽一次跟头,而且很可能是那种能 教会我们一些原本学不到的东西的方式。

一份松散的时间线

第一周:让 Flask 跑起来,用 React 渲染出点东西,并且 创建一张 SQLite 表而不把它搞坏。

第二周:让各个部分开始"对话"。前端连后端,后端连数据 库,尽量少一点恐慌。

第三周起:开始搭建真正的功能 - 登录、档案、出勤、成绩。

这份时间线能否在现实面前活下来,还有待观察。现实往往 自有主张。

为什么这重要

Archiviette 大概不会给我们班以外的世界带来太大改变, 而且很长一段时间里,它可能都不会显得多么亮眼。但它会 是属于我们自己的东西 - 是被建造出来的,而不是照本宣 科拼凑出来的,而这份区别,正是我在这一切开始之前就一 直在追寻的东西。

我们已经做好了在这件事上笨拙一阵子的准备。据我所知, 这大概就是学习本身所要求的东西。

接下来

随着项目推进,我们会继续记录下去。当有东西跑通了,会 记在这里。当有东西坏掉了 - 而它肯定会坏 - 也会记在 这里。

等仓库里有值得展示的东西了,链接自会附上。目前,它仍 是一个私密的结构,静候被填满。
